## Конкретизация компонентов

UIKit/SnapKit сохраняются; новая SwiftUI-архитектура не вводится. Новый общий Views/Components/CasePropertiesFormView.swift собирает существующие селекты/toggle в группы и используется созданием и единым редактором. PropertiesDetailCaseViewController можно удалить только после проверки отсутствия вызовов; данные enum/menu не удаляются.

GeneralCaseTextField получает отдельный режим оформления с сохранением текущего значения по умолчанию для CreatingProjectViewController. Поле сообщает изменение фокуса, высоты и валидности; счётчик и подсказка появляются у фокусного поля. Проверка 500 учитывает ввод/вставку и составной ввод, не ломает marked text и позицию курсора; лимит уже существующих полей не меняется.

CustomSelectableView остаётся единственным открывающим меню control: вся строка нажимаема, маркер/стрелка декоративные. Existing menuItem.id, набор опций и изображения внутри меню сохраняются. Без новой шкалы приоритетов. Значения ничего/не задано показывают текст без точки и пустого промежутка.

Маркеры берутся из AppTheme.Palette: priority high→warning, medium→info, low→secondaryText (как смысл существующих badges); severity blocker/critical/major→danger, normal→info, minor/trivial→success; nothing без маркера. Цвет точки не заменяет полную подпись и не меняет enum/сетевое значение. Для layer/behavior/type/status/automation дополнительных точек нет.

Исходный bool toggle хранится в модели; каждое изменение проходит через updateValue, чтобы обновлялась доступность сохранения. Фиксированная высота 40 снимается; новая строка растёт с текстом.

При fetch/re-render/смене темы поля рисуются из текущего черновика. Не затирать его исходным testCase при каждом обновлении UI.

Редактор использует существующую навигацию. В один GeneralDetailCaseViewController добавить общий блок свойств между условиями и шагами, удалить старые внутренние вкладки/жесты. StepCell сохраняет имеющийся безопасный рендеринг action, но не удаляет необходимые переносы; показывает expectedResult либо пояснение его отсутствия. Read-only шаги/вложения/nested data не вырезаются из draft/payload.

## Каталог родителя

Новые файлы: ViewControllers/CreatingVC/SuitePickerViewController.swift, ViewModel/SuitePickerViewModel.swift, Data/SuiteCatalogLoader.swift. В loader вынести повторно используемые обход страниц/дедупликацию/сбор пути из TestEntitiesViewModel; существующий loadCatalog становится его потребителем. Переписывать остальную загрузку кейсов/поиск репозитория не нужно.

Использовать существующий HomeRepository.suites, текущие owner/project Realm-методы и SessionStamp. Не вызывать TestEntitiesViewModel.reload только ради каталога: он также загружает кейсы. Публиковать/помечать полный каталог после всех страниц; частичная ошибка не заменяет кеш полным пустым списком. Поиск локален по полному каталогу (название/путь), не требует нового endpoint; при наличии только неполного кеша показать ограниченное состояние и retry.

Пути собираются по ID, с защитой циклов; отсутствующий предок — «Путь недоступен» с ID для различения одноимённых строк. Корень nil, входной 0 нормализуется. Предвыбор — из parentId/suiteId соответствующего черновика, а не неизменного parentSuiteId исходного контекста.

Нажатие возвращает ID и сведения для подписи в активный при открытии тип; closing без выбора не вызывает setter. Перед применением подтвердить текущую сессию/проект. Родитель кейса отправляется из draft.suiteId в dictOfValues, этот существующий путь сохранить.

Каталог разрешён только для создания. Сам набор/потомки исключаются лишь в отдельном будущем редакторе набора, которого в этой реализации нет.

## Сохранение и черновики

В обеих VM добавить приватно управляемое observable isSaving с main-thread уведомлением UI и защитой от конкурентного запроса. Общая валидность title.trimmingCharacters; editor дополнительно dirty. Create также недоступно для активного snapshot, уже подтверждённого предыдущим успешным созданием: это следует из обновлённого baseline/active dirty. Флаг результата сбрасывается до новой попытки и не заменяет подтверждение текущего ответа. Сохраняется захваченный snapshot; UI/смена типа/уход блокируются на время запроса.

Создание VM.hasUnsavedChanges относится только к активному типу. Контроллер ProjectDraft уже учитывает оба через initialSuite/initialCase: сохранить это различие. Обычная кнопка отправляет только активный тип. ProjectDraft.saveDraft для существующего «Сохранить и перейти» координатора может отправить оба dirty-типа последовательно — этот отдельный сценарий сохранить, не вызывать его из обычного закрытия.

После обычного успеха синхронизировать VM baseline и snapshot контроллера для отправленного типа. Если другой draft dirty, последующее закрытие обязано предложить продолжение/отмену, а не молча закрыть форму. При продолжении переключить сегмент и модель на оставшийся несохранённый тип, сохранив его ввод. Обычный успех не создаёт его автоматически. Возврат к уже созданному типу не включает Create для идентичного подтверждённого снимка; только изменение его данных образует новый черновик и позволяет новое обычное создание. Дополнительная кнопка копирования/сброса не вводится. После частичного координаторского успеха уже сохранённый тип не отправляется повторно.

После неуспеха ввод/dirty остаются, saving снимается, доступны действия. Старый owner/session response не принимается как новый успех, не закрывает форму и не меняет кеш.

Direct close/Back/gesture/tab: два действия «Продолжить редактирование / Отменить изменения»; применять существующий ProjectSwitchGuard для stay/discard без третьего Save. Глобальные смена проекта/токена/выход сохраняют существующий coordinator save/discard/stay. MainTabbarViewController добавляет узкий guard смены вкладки только при активном draft; общий coordinator не дублировать. На время saving все доступные уходы заблокированы. Контроль клавиатуры восстанавливает прежнюю видимость вкладок.

## Итог критики плана

Дополнено перед реализацией 9 октября 2026:

- ProjectDraft сообщает занятость с безопасным значением по умолчанию для старых форм. Координатор и ProjectSwitchGuard блокируют save/discard/переход для любого занятого участника до фильтра dirty, а после ожидания решения проверяют занятость повторно. Диалог ухода не открывается повторно.
- SuiteCatalogLoader получает проверку текущего поколения потребителя и проверяет её после await и перед записью кеша. Закрытие, отмена или retry не дают старому ответу опубликовать каталог, очистить кеш или применить родителя.
- При отсутствии total/filtered завершение определяется пустой/неполной страницей размера 50; полная первая страница не означает полный каталог. Проверка нескольких страниц без счётчиков обязательна.

Проведена независимая read-only проверка. Её замечание о повторной отправке уже созданного снимка после продолжения работы со вторым черновиком внесено в правила и регрессионный сценарий. Повторный вердикт — OKAY, блокирующих замечаний не осталось. Проверены восемь пунктов плана, существующие ссылочные исходники и локальные ссылки. Это статическая готовность плана, не подтверждение работы будущего кода.
