## Детали реализации

AuthViewController использует UIScrollView, ограниченный сверху safe area, снизу keyboardLayoutGuide. Ширина вертикального stack равна viewport минус 40 pt. Его верхний отступ вычисляется по fitting-height: max(24, (viewportHeight − contentHeight) / 2 − 32). Высоты контролов минимальные, текст переносится и растёт. Фокус и сообщение об ошибке прокручиваются в видимую область.

Делегат поля — контроллер; общий TextFieldWithPadding не изменён. После пользовательского снимка здесь применяется локальный AuthTokenTextField с явной геометрией боковых элементов и текста/placeholder. Рамка определяется по приоритету неверный токен → фокус → обычная. Переключатель сохраняет текст и UTF-16 позиции выделения, не переоткрывает клавиатуру. Подпись поля остаётся постоянной. Ошибки озвучиваются один раз; секрет не присваивается accessibility label/value вручную.

Все способы входа используют один guard и идентификатор запроса. Демо передаёт QASE_DEMO, не подменяя пользовательский ввод. До запуска Task UI синхронно блокируется. Сервис захватывается отдельно, self остаётся слабым через await. willMove(toParent: nil) инвалидирует идентификатор и отменяет Task; поздний ответ не изменяет интерфейс. Обычный уход в фон не отменяет запрос.

Публичные сигнатуры, Keychain, порядок активации сессии и RootViewController не менялись. HTTP-исправление ограничено APIManager.auth(by:); оно также даёт существующей форме замены токена корректные типизированные ошибки. Ни сырые ответы сервера, ни сообщения с возможным отражением токена не выводятся на экран.
