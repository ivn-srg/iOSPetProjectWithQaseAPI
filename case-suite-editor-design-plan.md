# Макеты форм кейсов и наборов

## Цель и границы

Создать пять итоговых листов форм в светлой и тёмной темах по текущей дизайн-системе. Код приложения, API и данные не изменяются. Редактор набора и новый выбор родителя — будущие интерфейсы; при создании кейса потребуется подключить выбор к suiteId. В существующем редакторе кейса перенос между наборами не добавляется.

## Зафиксированные исправления плана

1. Существующие формы отделены от концепта редактора набора и нового выбора родителя.
2. У единой формы задан полный порядок: основные данные, условия, расположение только при создании, классификация, тип/уровень, автоматизация, read-only шаги только при редактировании.
3. Определены выбор родителя, отмена, одинаковые названия/пути, загрузка и ошибки каталога.
4. Добавлены состояния клавиатуры, сохранения, ошибки и выхода с обоими черновиками создания.
5. Проверка графики отделена от проверки приложения; исходные снимки не воспроизводятся как якобы точные скриншоты.

## Дизайн

Базовый экран 402 × 874 pt; поля 20 pt, карточки radius 16 pt, группы разделены 16–24 pt, интерактивные строки минимум 52 pt. Подписи постоянные около 13 pt, ввод и значения около 17 pt. Высота увеличивается с текстом. Палитра/SF Pro/SF Symbols соответствуют приложению, тема наследуется.

Создание: компактный заголовок «Создание», закрытие/«Создать», один сегмент «Набор / Кейс». Редактирование: ID, Back/«Сохранить», без разделов «Общие / Свойства». Название — единственное обязательное поле, пробельное значение недопустимо. Сохранение недоступно без изменений. Для существующих текстовых полей сохраняется лимит 500 символов.

Набор: название/описание → предусловия → родитель. Кейс: название/описание → предусловия/постусловия → родитель только при создании → серьёзность/статус/приоритет → поведение/тип/слой → автоматизация/isFlaky → шаги только при редактировании. Подпись isFlaky — «Нестабильный тест», вместо ошибочной «Есть вложенность».

Шаги — нумерованные карточки действия и ожидаемого результата, без add/edit/reorder. Предусмотреть длинный текст, «Ожидаемый результат не задан» и «Шагов пока нет».

Выбор родителя: модальная панель, Close, поиск, фиксированный «Корень проекта», названия/полные пути/checkmark. Тап выбирает в черновик и закрывает, Close сохраняет предыдущий выбор. Только текущий проект; для будущего перемещения набора исключить его самого и потомков.

## Приёмка

Полноэкранные пары имеют одинаковые данные и позицию прокрутки. Крупный шрифт и длинный текст не достигаются уменьшением шрифта; поля растут. Создание не содержит нижних вкладок, редактор кейса сохраняет вкладки приложения. При клавиатуре ввод не перекрыт, верхнее действие доступно. Подтверждение закрытия учитывает оба черновика, без обещания автоматически создать обе сущности.

Сборка, компиляция и тесты не запускаются. Визуальная оценка AI-макетов не подтверждает поведение или пиксельное совпадение приложения.

## Повторная критика 8 октября 2026

Пять листов и запросы генерации сохранены в [Design/Concepts/EntityForms](Design/Concepts/EntityForms/README.md). Статус — **требуются правки**, передача в реализацию пока не подтверждена. Подробные наблюдения и порядок доработки: [REVIEW.md](Design/Concepts/EntityForms/REVIEW.md).

Первоочередные исправления: одинаковое состояние toggle в обеих темах; тёмные подтверждения и ошибки; единая геометрия 402 × 874 pt; путь выбранного родителя; связные срезы скролла. Дополнить длинные значения, крупный текст, клавиатуру кейса, лимит 500 символов и выход редакторов. Последняя просьба пользователя — критика; автоматическая перегенерация в этом проходе не выполнялась.
