# Разработка и проверка

Агенты не запускают сборки, компиляцию, тесты, анализ через сборочную систему и CI. Все команды этого документа предназначены **только для самостоятельного запуска пользователем**. Правила: [AGENTS.md](../AGENTS.md); памятка: [CLAUDE.md](../CLAUDE.md).

## Окружение и зависимости

Нужны macOS, Xcode с поддержкой iOS 18.6 и симулятор либо устройство с iOS не ниже 18.6. В конфигурации CI указаны Xcode 26.3 и iPhone 16 с iOS 18.6; это настройка workflow, не подтверждение локального окружения.

Откройте `QaseAPIProj.xcodeproj`, дождитесь подготовки Swift Package Manager и выберите схему `QaseAPIProj`. Для устройства задайте свой Signing Team. CocoaPods не требуется: приложение использует SnapKit и Realm Swift через SPM.

Минимальный SnapKit в проекте — 5.7.1; Realm Swift берётся из ветки `community`. Точные ревизии, включая транзитивный realm-core, находятся в [Package.resolved](../QaseAPIProj.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved). Не обновляйте зависимости как побочный эффект изменения документации. Swift language mode — 5; `.swiftformat` настроен для Swift 6.2 в этом режиме.

```bash
open QaseAPIProj.xcodeproj
xcrun simctl list devices available
xcodebuild -list -project QaseAPIProj.xcodeproj
```

Токен вводится в приложении, не в исходниках. Для ознакомления нажмите «Попробовать демо»; долгий жест на логотипе сохранён. Демо и UI-tests используют mock-путь и отдельный кеш.

## Команды пользователя

Сборка для симулятора:

```bash
xcodebuild build \
  -project QaseAPIProj.xcodeproj \
  -scheme QaseAPIProj \
  -destination 'generic/platform=iOS Simulator' \
  CODE_SIGNING_ALLOWED=NO
```

Unit-проверки:

```bash
xcodebuild test \
  -project QaseAPIProj.xcodeproj \
  -scheme QaseAPIProj \
  -destination 'platform=iOS Simulator,name=iPhone 16,OS=18.6' \
  -only-testing:QaseAPIProjTests
```

UI-проверки используют тот же вызов с `-only-testing:QaseAPIProjUITests`. Имя и OS замените на установленный симулятор. Для отдельной проверки: `-only-testing:QaseAPIProjTests/QaseAPIProjTests/checkValidURL`.

Исходники unit-проверок используют Swift Testing, UI-проверок — XCTest. Общие схемы сохранены в проекте. UI-тестовый аргумент `UITests` выбирает mock-сеть, credentials в памяти и изолированный Realm; реальные токены в тестовых данных не нужны.

| Область | Исходники проверок |
|---|---|
| Авторизация и замена токена | AuthScreenTests, AuthHTTPTests, TokenReplacementTests, AuthScreenUITests |
| Сессии, проект и граф зависимостей | ArchitectureRegressionTests, ProjectLifecycleTests, ProjectSwitchTests |
| Кеш, Home и пагинация | IdentityCacheTests, CacheManagementTests, HomeDataTests, HomeViewModelTests, PagedReadViewModelTests, RepositoryRefinementTests |
| Формы и родитель | FormComponentTests, FormDraftTests, FormParentPickerTests |
| Настройки, tokens и UI | AppSettingsTests, DesignTokenTests, HomeScreenUITests, QaseAPIProjUITests |

[CI](../.github/workflows/ios-ci.yml) содержит сборку, unit/UI-проверки и сохранение результатов. Наличие workflow и тестовых исходников не подтверждает успешный прогон; актуальный результат проверяется отдельно пользователем.

## Ручная приёмка

Проверяйте RU/EN, обе темы, ширины 320/402 pt, крупный системный шрифт и VoiceOver. [Дизайн-концепты](../Design/DESIGN_SYSTEM.md) не заменяют актуальные скриншоты приложения.

| Сценарий | Что проверить |
|---|---|
| Авторизация | Пустой/пробельный и неверный токен, 401/403 и прочие HTTP-отказы, offline/timeout, повторное нажатие, успешный вход, демо без потери введённого текста |
| Поле токена | Ключ слева, placeholder, боковые зоны 44 pt и символы 22 pt, скрытие/показ, выделение и следующая вставка, фокус, клавиатура и прокрутка к ошибке; секрет не озвучивается в сообщениях |
| Смена сессии | Проверка/замена токена, повтор того же токена без сброса черновиков, отказ записи credentials, отмена, выход и поздние ответы; предупреждение об отказе очистки старого кеша после смены root |
| Проекты и Home | Выбор/смена проекта, начальное/пустое/cache/error состояние, активный запуск, история и OfflineBanner; нижний контент не перекрывается вкладками |
| Репозиторий | Поиск, длинные пути, вложенный набор, пагинация с/без total, повторная страница и частичная загрузка; поиск не удаляет полный кеш |
| Создание | Проект в standard; набор и кейс в grouped; два черновика, пробельное название, Unicode и лимит 500 символов, нетронутый длинный серверный текст; начало ввода 16 pt, минимум 44/56 pt, рост поля и индикатор ошибки/фокуса |
| Родитель и свойства | Корень nil, полный каталог проекта, длинные/одинаковые названия, путь, поиск, loading/error/retry/empty; отмена сохраняет выбор и второй черновик; меню, маркеры и toggle |
| Редактор кейса | Все условия/свойства видны, сохраняются скрытые серверные поля и родитель, шаги read-only и пустое состояние; все шаги доступны над вкладками |
| Сохранение и уход | Повторное действие, ошибка, частичный успех без повторной отправки успешного черновика, продолжение второго; Back, жест, закрытие, вкладка/проект/токен/выход; отмена сохраняет ввод, saving блокирует уход |
| Запуски и дефекты | Списки/подробности, кеш, loading/empty/error/retry, пагинация; интерфейс просмотра не обещает выполнение запуска |
| Настройки | Тема после перезапуска и в модальных экранах, язык через iOS, замена токена, отклонённый кандидат сохраняет сессию, данные из Bundle; очистка загруженного кеша сохраняет авторизацию, проект и историю |
| Заголовки и доступность | Сворачивание заголовка, вся кнопка проекта нажимается, baseline/длинные метаданные, прокрутка чипов без конфликта с жестами; полные значения VoiceOver и один статус загрузки |
| Клавиатура и адаптация | Dynamic Type, перенос текста, safe area, interactive dismissal; последний элемент виден, нет двойных нижних отступов и декоративных маркеров в accessibility-фокусе |

## Ограничения и обслуживание

- Статическая сверка не подтверждает компиляцию, прохождение тестов, устранение предупреждений SDK/зависимостей или работу на устройстве. Сборка, тесты и визуальная приёмка последних изменений остаются пользовательской проверкой.
- Кеш поддерживает чтение ранее загруженного; offline-запись и синхронизация не реализованы. Отказ кеширования сообщается отдельно и не скрывает свежие данные.
- Grouped-геометрия уточнена после макетов v3: они показывают структуру и маркеры, а не точное нынешнее оформление полей.
- Редактор набора, выполнение Runs и media workflow остаются задачами [roadmap](ROADMAP.md). Сетевые маршруты сами по себе не добавляют эти функции.
- [.swiftformat](../.swiftformat) задаёт форматирование. Оно и выбранные правила SwiftLint без компиляции не заменяют typecheck и пользовательские прогоны. Эта очистка не изменяет Swift-файлы.
- `build`, `DerivedData`, Logs/TestResults и пользовательские настройки исключаются из Git. После удаления кеша Xcode заново подготовит зависимости и индексы; `Package.resolved` и общие схемы сохраняются.

Временные планы и журналы завершённых работ не нужны в корне. Действующие контракты находятся в [архитектуре](ARCHITECTURE.md) и дизайн-документации; история остаётся в Git.
